SSO、OIDC 和 API Key 都与认证有关，但它们所在的层级不同，生命周期和使用对象也不同。

## SSO 解决登录会话

SSO 通常代表某个用户已经在网页或服务中完成登录。它可能表现为 Cookie、会话令牌或平台内部凭据。

它适合回答“这个用户是否已经登录”，但不自动等于某个开发者 API 的调用凭据。

## OIDC 表达可验证身份

OIDC 在 OAuth 2.0 之上增加身份层，常用于让服务确认调用者是谁。具体系统可能使用短期令牌、受众限制和签名验证。

令牌能否使用，取决于签发方、受众、作用域和有效期。两个令牌都采用 JWT 格式，不代表它们能够互换。

## API Key 标识调用权限

API Key 通常由目标 API 发放，用于标识调用方、选择权限和记录用量。它可能没有用户登录会话，也不包含完整身份信息。

诊断认证问题时，应当分别确认：

- 凭据由谁签发；
- 发送给哪个目标；
- 使用什么请求位置和协议；
- 权限范围与有效期是什么；
- 失败发生在本地校验还是远端拒绝。

把这些边界写清楚，比记住凭据的文件扩展名更可靠。
