## Neverless 在备用路线中做什么

[总览文章](/moonlit-blog/posts/crypto-to-wise-route-in-progress/)把 Neverless 放在 Kraken 的备用位置。它不是一个普通的收币地址，而是要连续完成三件事：

1. 接收从币安提出的 USDT 或 USDC。
2. 把稳定币换成 EUR。
3. 通过 SEPA 把 EUR 转进 iFAST。

三件事任何一项不成立，这个平台节点就没有接通。只完成充值但换不了 EUR，或者已经换出 EUR 却没有可用的 SEPA 收款账户，对整条路线来说都还停在中间。

```text
中国地区资料注册 + KYC
→ 创建稳定币充值入口
→ Neverless 出现可用 USDT / USDC
→ 稳定币换成 EUR
→ Neverless 出现可用 EUR
→ EUR SEPA 提现
→ iFAST 实际收到 EUR
→ iFAST 继续处理 EUR 到 GBP
```

Neverless 这个节点的最终完成标准，是 iFAST 实际收到从 Neverless 提出的 EUR。

## 中国地区资料注册与 KYC

### 与 Kraken 最直接的区别

[Kraken 主路线](/moonlit-blog/posts/kraken-gbp-fps-offramp/)需要按英国区准备账户，后面走 GBP 和 FPS。Neverless 的注册条件不同：涉及国家和地区的信息可以全部选择中国。

这是它作为备用路线的核心价值。它不需要先满足 Kraken 主路线的英国区条件，而是用中国地区资料建立账户，再尝试 EUR 和 SEPA 这条法币出口。

但“地区可以选中国”只解决地区选择问题，不代表注册表单提交后就自动完成 KYC，更不能证明 EUR 和 SEPA 功能一定已经可用。

### 注册完成仍然有多个状态

| 状态 | 能说明什么 | 还不能说明什么 |
| --- | --- | --- |
| 注册表单已提交 | 账户创建流程已经开始 | 不能说明 KYC 已通过 |
| 可以登录 | 账户存在并可访问 | 不能说明充值和法币功能可用 |
| KYC 已通过 | 身份验证完成 | 不能自动证明 EUR/SEPA 入口存在 |
| EUR/SEPA 入口可见 | 当前备用路线需要的功能已经出现在账户中 | 仍未验证充值、兑换和提现 |

目前不知道 Neverless 对中国地区账户具体接受哪种身份证件，也没有完整的 KYC 页面和审核记录。因此这篇不猜身份证、护照或其他证件是否可用，也不编造审核时长。

注册时使用自己的真实资料，并设置自己控制的登录凭据和双重验证。这里不展开安全教程，只把账户地区、KYC 状态和 EUR/SEPA 入口作为需要记录的结果。

## 在 Neverless 创建稳定币充值入口

这一步与[币安买入并提走 USDT](/moonlit-blog/posts/binance-buy-usdt-basics/)衔接。币安负责发送，Neverless 负责生成接收参数。

正确顺序是：

1. 在 Neverless 打开充值或接收入口。
2. 查看当时实际允许充值的稳定币。
3. 选择 USDT 或 USDC。
4. 查看该资产当前支持的网络。
5. 选择网络并生成地址。
6. 记录页面显示的最低充值数量、确认要求和附加标识。
7. 再回币安使用相同资产、相同网络和这条地址提币。

不能先在币安随便挑一条便宜网络，再假定 Neverless 一定支持。资产和网络必须同时匹配：USDT 不能发进 USDC 入口，同一种 USDT 也不能在两端选择不同网络。

这里不列 Neverless 当前支持的具体网络，也不写固定最低充值数量。平台支持和门槛都可能变化，只能读取本次充值页面。

## 稳定币充值不是一个瞬间状态

从币安提交提币到 Neverless 余额可用，中间有几种不同状态：

| 状态 | 发生在哪里 | 表示什么 |
| --- | --- | --- |
| 提币已提交 | 币安 | 币安接受了提币请求 |
| 出现 TxID | 币安与区块链 | 交易已经广播，可以查询链上状态 |
| 链上确认中 | 区块链 | 交易正在获得确认 |
| Neverless 检测到充值 | Neverless | 平台已经发现交易，但余额可能仍在等待 |
| 稳定币余额可用 | Neverless | 资产可以用于下一步兑换 |

币安显示提币完成，不等于 Neverless 余额已经可用；区块浏览器出现确认，也不能代替 Neverless 的内部记账状态。

充值环节的完成标准是 Neverless 账户里实际出现可用的 USDT 或 USDC。网络不匹配、资产不匹配，或者金额低于 Neverless 当时显示的最低充值数量时，都不能预设平台会正常记账。

这篇把充值状态写到可用余额，但不声称实际充值已经完成。

## 把稳定币换成 EUR

Neverless 节点的产物是 EUR，而不是把稳定币从币安搬到另一个应用里存放。稳定币成为可用余额以后，还需要完成 Crypto-to-Fiat。

### 先确认实际兑换路径

打开账户后要确认：

- Neverless 实际支持 USDT/EUR、USDC/EUR，还是需要其他路径。
- 页面提供的是简单兑换、交易入口，还是其他形式。
- 当前报价是多少。
- 页面显示哪些费用。
- 最终预计得到多少 EUR。

如果存在直接的稳定币到 EUR 路径，就只需要一次兑换；如果实际页面没有直接路径，才需要研究中间步骤。不能在没有查看账户前，先假设交易对和兑换方式一定存在。

### 比较最终结果，而不是只看“零手续费”

如果平台提供不同入口，低损耗路线需要比较的是最终得到的 EUR，而不是单看某一处写了多少手续费。

至少记录：

- 使用的稳定币与数量。
- 兑换入口。
- 页面报价。
- 买卖价差或报价差异。
- 平台显示的费用。
- 预计 EUR 数量。
- 实际成交后的 EUR 数量。

即时兑换强调一次确认完成；交易入口可能提供市价或限价等不同订单方式。市价更强调立即成交，限价控制价格但不保证立即成交。实际选择要看 Neverless 当时真正提供什么，以及最终报价和成交结果。

兑换环节的完成标准不是订单已经提交，而是订单已经成交，Neverless 法币余额里出现可用 EUR。

## 通过 EUR SEPA 提到 iFAST

### 前置条件是 iFAST 已经可以接收 EUR

SEPA 提现需要一个银行收款账户。备用路线计划使用 iFAST 的同名 EUR 收款信息。

当前 iFAST 尚未开户。开户需要的地址证明仍在验证，所以 Neverless 到 iFAST 的 SEPA 提现现在不具备端到端测试条件。

等 iFAST 开好后，Neverless 侧需要完成：

1. 在 EUR 提现页面确认实际存在 SEPA 方式。
2. 添加 iFAST 的同名 EUR 收款账户。
3. 根据页面填写收款人、IBAN、BIC 或其他要求字段。
4. 核对最低提现、平台手续费和预计处理信息。
5. 输入 EUR 金额并提交。
6. 等待 iFAST 银行账户实际出现 EUR 入账。

所有字段和数值都以当次页面为准。这里不写固定提现门槛、手续费和到账时长。

### SEPA 提现也有多个状态

| 状态 | 能说明什么 |
| --- | --- |
| 银行账户已添加 | Neverless 已保存收款信息，还没有发起提现 |
| 提现已提交 | Neverless 接受了 EUR 提现请求 |
| Neverless 处理中 | 请求仍在平台内部处理 |
| Neverless 已发送 | 平台侧已经执行转账，但不能代替银行查账 |
| iFAST 实际入账 | Neverless 节点才算端到端完成 |

完成标准是 iFAST 账户中实际出现对应 EUR 入账，而不是 Neverless 显示“已发送”。当前这一步尚未实测。

## EUR 到 GBP 是备用路线额外的一层

Kraken 主路线直接产出 GBP，进入 iFAST 后可以继续准备 GBP FPS 到 Wise。Neverless 备用路线产出 EUR，所以 iFAST 收到 EUR 后还要处理一次 EUR 到 GBP。

```text
Kraken 主路线
稳定币 → GBP → FPS → iFAST GBP → Wise

Neverless 备用路线
稳定币 → EUR → SEPA → iFAST EUR → EUR/GBP → iFAST GBP → Wise
```

多出这一层意味着需要额外记录：

- EUR/GBP 实际汇率。
- 换汇报价或价差。
- 换汇手续费。
- 换汇前后的 EUR 与 GBP 数量。
- 处理时间和余额状态。

没有实测数据，不能直接判断备用路线的总成本一定更高。但 EUR 到 GBP 是客观存在的额外处理层，比较主路线和备用路线时必须把它算进去。

这篇不展开 iFAST 内部如何换汇，但不会假装 Neverless 的 EUR 可以无损、无步骤地变成 Wise 所需的 GBP。

## Neverless 与 Kraken 的路线差异

| 对比项 | Neverless 备用路线 | Kraken 主路线 |
| --- | --- | --- |
| 注册地区 | 国家和地区信息可以选择中国 | 当前路线需要英国区 |
| KYC 证件 | 尚未确认 | 当前确认可以使用身份证 |
| 法币产物 | EUR | GBP |
| 银行通道 | SEPA | FPS |
| iFAST 后是否还要处理 EUR/GBP | 需要 | 不需要 |
| 当前实测状态 | 未跑通 | 未跑通 |

两条路线都没有端到端数据，不能判断哪条更快、更便宜或更稳定。Neverless 解决的是中国地区资料与 EUR/SEPA 备用出口，代价是后面多出 EUR 到 GBP 的处理。

## 整个 Neverless 节点怎样互相依赖

```text
中国地区资料注册 + KYC 通过
→ EUR/SEPA 功能实际可见
→ 创建稳定币充值入口
→ Neverless 出现可用稳定币
→ 稳定币/EUR 兑换完成
→ Neverless 出现可用 EUR
→ iFAST 同名 EUR/SEPA 账户已开通
→ Neverless 提交并处理 SEPA 提现
→ iFAST 实际收到 EUR
```

每一步都为下一步提供入口。KYC 没通过，后续功能无法确认；稳定币没有成为可用余额，就没有资产可以兑换；EUR 没有实际成交，就没有法币可以提现；iFAST 没开好，就没有 SEPA 收款账户。

## 实际操作时应该记录什么

| 阶段 | 记录字段 |
| --- | --- |
| 注册与 KYC | 国家/地区选择、证件类型、KYC 状态、EUR/SEPA 入口是否可见 |
| 稳定币充值 | 资产、网络、地址首尾、最低充值数量、TxID、状态变化、可用时间 |
| 稳定币换 EUR | 兑换入口、报价、价差、费用、实际 EUR 数额 |
| SEPA 提现 | 提现方式、最低提现、提现金额、平台费用、Neverless 状态、iFAST 入账时间 |
| iFAST 后续换汇 | EUR/GBP 汇率、费用、换汇前后余额 |

这些数据用于计算备用路线的真实损耗和定位卡点。公开写文章时，不需要暴露完整充值地址、银行账号或身份材料。

## 现在真正卡住的地方

这篇已经把 Neverless 从中国地区资料注册写到 EUR/SEPA 出金的完成标准。当前节点尚未跑通：Neverless 的注册、充值和兑换缺少实际记录，iFAST 又被地址证明卡在开户之前。

只要 iFAST 还没有可用的 EUR/SEPA 收款账户，Neverless 节点就无法验证到最后一行。最终是否跑通，要以 iFAST 实际收到从 Neverless 提出的 EUR 为准。
