> 这篇是[从买币到 Wise 的完整出金链路](/moonlit-blog/posts/crypto-to-wise-route-in-progress/)中的第一篇基础分篇。

## 为什么从买币写起

整条路线后面还有 Kraken 或 Neverless、iFAST 和 Wise，但不管下游怎么走，起点都是一笔可以从币安转出的稳定币。

第一步不是选链，也不是复制外部地址，而是在币安把 USDT 买到手，并弄清楚买完以后它实际在哪个账户里。本文会继续写到币安侧的链上提币，但不展开接收平台怎样充值和入账。

之所以先写币安，是因为它在国内 C2C 支付方式上的支持最完整。除了银行卡转账，广告方还可以支持支付宝和微信。对国内用户来说，这比只支持银行转账的入口灵活得多，也是我把币安放在买入端的主要原因。

这里说的是支付宝、微信作为订单中明确列出的付款方式。它和卖方要求把聊天转移到微信、脱离币安订单完全不是一回事。

## USDT 和 USDC 是什么

USDT 和 USDC 都是以美元价值为参照的稳定币，但它们不是同一种资产，发行方也不同。

对这条出金路线来说，最重要的不是比较谁更适合长期持有，而是确认后面的平台收什么：Kraken 或 Neverless 是否支持这个币种，又支持它运行在哪些网络上。

同样写着 USDT，也可能存在于不同网络。币安有某种 USDT，不等于接收平台支持它的每一种网络；USDT 和 USDC 之间也不能直接当作同一种币发送。

在这套路线里，稳定币只是 Crypto-to-Fiat 之前的中间资产：先在买入端获得，再提到 Kraken 或 Neverless，最后换成 GBP 或 EUR。

## C2C / P2P 实际在做什么

币安的 C2C 和 P2P 在这里指同一类交易：买方与广告方直接完成法币付款，币安在订单期间托管卖方的数字资产。

基本流程是：

1. 卖方发布广告，写明币种、单价、订单限额和支持的付款方式。
2. 买方选择广告并下单，币安锁定相应数量的数字资产。
3. 买方根据订单页面提供的收款信息，直接向卖方支付法币。
4. 买方标记已付款，卖方确认到账后放币。
5. 币安把托管的资产释放到买方账户。

法币不是先转给币安，再由币安替我买币。它从买方的支付宝、微信或银行账户直接转给订单中的卖方；币安托管的是另一端的 USDT。

## 一条广告不只有单价

打开 C2C 买入页面后，最显眼的是单价，但真正决定能否下单的还有其他字段：

| 字段 | 需要确认的内容 |
| --- | --- |
| 单价 | 一单位 USDT 对应多少法币 |
| 可用数量 | 广告方当前还能出售多少 USDT |
| 订单限额 | 单笔订单允许的最低和最高法币金额 |
| 付款方式 | 是否支持支付宝、微信或自己的其他付款账户 |
| 完成率 | 广告方历史订单的完成比例 |
| 历史订单量 | 广告方有多少可供参考的历史交易 |
| 广告条款 | 付款时限及其他下单前需要知道的条件 |

单价最低的广告不一定真的能买。它可能设置了更高的最低金额，也可能只接受自己没有的付款方式。实际选择时，要把单价、限额、付款方式和最后能得到的 USDT 数量放在一起看。

## 买到以后，币在哪里

C2C 买到的 USDT 通常先进入币安的资金账户。这里至少要区分三个概念：

- **资金账户**：承接 C2C 等功能中的资产。
- **现货账户**：用于币币交易等功能。
- **链上地址**：区块链上的充值或提币地址。

资金账户和现货账户都属于币安内部账户。它们之间的划转只是平台账本变化，不是链上提币。只有把资产发送到币安之外的区块链地址，才进入后半部分要处理的链上转移。

币安的账户结构和入口可能随版本变化。买币后先看资产实际落在哪个账户，再根据当时的提币入口决定是否需要内部划转，不要把旧界面的按钮位置当成固定规则。

## 在币安 C2C 买入 USDT

下面只写不依赖具体界面版本的操作顺序。

### 1. 准备账户

先完成币安账户注册和 KYC，并准备本人名下、实名信息一致的付款账户。支付宝、微信和银行卡是否出现在某条订单里，取决于广告方列出的付款方式。

### 2. 进入 C2C 买入区

在币安 APP 或网页端进入 C2C / P2P，选择“买入”和 USDT，再按实际法币金额、支付宝、微信或其他可用付款方式筛选广告。

这里不假定按钮一定处在某个固定位置。界面会变，但要完成的筛选条件不会变。

### 3. 检查广告

下单前至少核对：

- 单价和最终可得的 USDT 数量。
- 自己的金额是否落在广告限额内。
- 广告方是否支持自己准备使用的付款方式。
- 完成率、历史订单量和广告条款。

如果广告最低限额高于准备买入的金额，即使价格再低也无法下单。

### 4. 下单并付款

下单以后，订单页面会显示应付金额、付款时限和收款信息。

只按照订单页面提供的信息付款，不向聊天中临时出现的其他账户转账。先在支付宝、微信或银行端完成真实付款，确认资金已经转出，再回到币安点击“已付款”。不能因为卖方催促就提前标记。

使用微信完成订单列出的微信付款没有问题；但不要因此把订单沟通也移到私人微信。交易记录、收款信息和后续申诉都应留在币安订单内。

### 5. 等待卖方放币

卖方确认收到法币后，才会释放平台托管的 USDT。“已付款”只表示买方已经声明转账，不代表 USDT 已经到账。

如果已经真实付款但卖方没有放币，应从订单内发起申诉，不要自行取消已经付款的订单。

### 6. 检查实际余额

收到放币通知后，回到币安资产页面检查币种和数量。聊天消息或截图都不能代替账户余额。

确认 USDT 已进入资金账户后，C2C 买入部分才算结束。接下来如果提币入口需要使用其他内部账户，再根据当前界面做内部划转。

## 最容易混淆的几个状态

- 点击“已付款”，不等于已经收到 USDT。
- 卖方说“已放币”，也不能代替自己检查资产余额。
- 低单价不等于广告可用，还要看限额和付款方式。
- 支付宝或微信付款账户应与币安实名信息一致。
- 资金账户里出现 USDT，只代表币还在币安内部。
- 买到 USDT，不等于已经完成币安提币。
- 币种名称相同，不等于发送方和接收方支持的网络相同。

## 资金账户有了 USDT，然后呢

走到这一步，币安资金账户里已经显示出 USDT 余额。但这仍然是币安内部账本中的余额。要把它发送到币安之外，需要发起提币。

这一部分只讨论币安侧的提币动作：选择网络、填写地址、查看最低提币数量和手续费、提交，再到提币记录里确认币安已经处理。外部平台的充值流程不放在这里。

## 常见的 USDT 网络

USDT 存在于多条网络上。币安在提币页面可能显示多个网络选项，每一个选项都有各自的最低提币数量和手续费。

| 网络 | 常见标签 | 地址格式特征 | 提币时要注意什么 |
| --- | --- | --- | --- |
| TRON | TRC20 | 通常以 `T` 开头 | 常见的 USDT 网络，仍要以币安当时显示的费用和最低数量为准 |
| Ethereum | ERC20 | 通常以 `0x` 开头 | 费用可能较高，并随网络和平台参数变化 |
| BNB Smart Chain | BEP20 | 通常以 `0x` 开头 | 不能仅凭 `0x` 地址把它当成 Ethereum |
| Arbitrum One | Arbitrum | 通常以 `0x` 开头 | 与 Ethereum 主网是不同的网络选项 |
| Polygon PoS | Polygon | 通常以 `0x` 开头 | 与 Ethereum、BSC、Arbitrum 都不能混选 |
| Solana | SOL / SPL | 与 EVM 网络不同 | 是否可选以及当时费用仍以币安页面为准 |

这张表只说明常见名称和地址特征，不表示币安在任何时刻都会开放所有网络。网络可能临时暂停提币，支持列表也可能调整。

## `0x` 地址不等于同一个网络

Ethereum、BNB Smart Chain、Arbitrum One 和 Polygon PoS 的地址都可能以 `0x` 开头。同一个地址格式可以出现在多条 EVM 网络上，但这些网络彼此独立。

所以网络是一个单独字段，不能从地址长相推导出来。外部地址标明属于哪条网络，币安就必须选择对应网络。地址能够通过格式校验，不代表网络一定选对了。

## 最低提币数量和手续费是两件事

提币页面最容易混淆的是两个数。

### 最低提币数量

这是币安在所选网络上允许提交的最低数量。低于它，提币订单无法提交。不同网络可以给出不同门槛，同一网络的门槛也可能调整。

我实际见过页面一会显示最低 2 USDT，一会变成 5 USDT，另一个时间或网络又是 10 USDT。它不是一个可以从旧文章里抄下来长期使用的常量。

### 提币手续费

这是币安在当次提币页面显示的平台费用。它同样会随网络或平台参数变化，而且不同网络之间可能相差很大。

平台显示的提币费不能直接当作链上的实时 gas。对实际操作来说，重要的是读取本次确认页面显示的费用，而不是猜它怎样计算，也不是拿上一次提币的数字继续使用。

## 还要看预计到账数量

输入提币数量并选定网络后，页面还会给出预计到账数量。不同版本可能用不同方式展示输入数量、手续费和最终到账，不能套用一个固定扣费公式。

因此，每次提币至少要同时读取：

- 当前网络的最低提币数量。
- 本次提币手续费。
- 本次预计到账数量。

这三个值都以提交前的确认页面为准。

## 在币安发起 USDT 提币

### 1. 准备地址和网络

先从外部钱包或平台取得 USDT 地址，并确认这个地址对应的网络。这里不展开外部平台的充值规则，只把地址和网络作为本次提币的输入。

### 2. 填写币安提币页面

在币安选择 USDT 提币，粘贴地址，再选择与外部地址对应的网络。不能为了省手续费，擅自改成另一条看起来更便宜的网络。

选择网络后，再输入提币数量，并读取页面实时显示的最低提币数量、手续费和预计到账数量。

### 3. 提交前核对

确认页面至少要检查：

- 币种是 USDT。
- 网络与外部地址要求一致。
- 地址开头和末尾与原地址一致。
- 提币数量达到当前网络的最低提币数量。
- 手续费和预计到账数量已经看清。

确认无误后，再提交并完成币安要求的账户验证。

### 4. 查看币安提币记录

提交后，币安提币记录会显示处理状态。交易被广播后，记录中通常会出现 TxID，也就是交易哈希，可以用来查看这次链上转账。

这篇在币安完成提币处理并生成相应记录的位置结束。TxID 和链上确认仍然是不同状态；这里只记录币安侧。

## 小额测试也受最低提币限制

“先转一小笔”不能机械理解成转 1 USDT。如果页面当前显示最低提币数量是 5 USDT，那么 1 USDT 根本无法提交。

测试金额首先要达到所选网络当时的最低提币数量，再结合手续费和预计到账选择一个合适的小额。即使刚刚查看过，提交下一笔之前也应重新读取页面，因为最低数量和手续费可能已经变化。

## 每次提币应该记录什么

因为最低数量和费用一直在变，每次真实提币最好留下当时的数据：

- 操作时间。
- 币种。
- 选择的网络。
- 地址首尾几位。
- 提币数量。
- 币安当时显示的最低提币数量。
- 币安当时显示的手续费。
- 预计到账数量。
- 币安提币记录状态。
- TxID。

这些信息足以复盘币安侧的提币。公开写文章时不需要暴露完整地址、平台账号或身份信息。
