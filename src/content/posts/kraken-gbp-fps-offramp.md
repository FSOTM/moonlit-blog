## Kraken 为什么是一个完整节点

在[总路线](/moonlit-blog/posts/crypto-to-wise-route-in-progress/)里，Kraken 不是一个普通的收币地址。它要连续完成三件事：

1. 接收从币安提出的 USDT。
2. 把 USDT 换成 GBP。
3. 通过 FPS 把 GBP 转进 iFAST。

三件事里任何一件不成立，这个平台节点就没有接通。注册了但无法完成充值没有用，USDT 到账后不能换成 GBP 也没有用，GBP 已经换出来却没有可用的 FPS 收款账户，资金仍然离不开交易所。

所以这篇不再停在 Kraken 注册，而是从开户条件一直写到 iFAST 实际收到 GBP 的完成标准。

```text
英国区 Kraken 账户 + KYC
→ 创建 USDT 充值入口
→ Kraken 出现可用 USDT
→ USDT 换成 GBP
→ Kraken 出现可用 GBP
→ GBP FPS 提现
→ iFAST 实际入账
```

## 英国区注册与身份证 KYC

### 为什么地区选择要在注册前决定

这条主路线选择 Kraken 的目的，是使用 GBP 和 FPS。对我当前设计的路线，Kraken 账户需要按英国区注册。

因此，注册时不能只以“先把账户建出来”为目标。能登录 Kraken，只能说明账户存在；它不能证明后面需要的 GBP 和 FPS 入口一定可用。地区条件应当在注册之前确认，而不是等 USDT 已经转入以后才检查。

### 账户地区与身份证件是两个条件

这里最容易混淆的是：

- **账户地区**：当前 GBP/FPS 主路线需要英国区。
- **身份验证证件**：当前确认可以使用身份证完成 KYC。

英国区路线不等于证件必须是英国护照或英国驾照。账户地区和 KYC 证件类型是两个不同概念。

注册页面如果还要求居住地址、国籍、税务居民、手机号或其他资料，应当根据实际页面填写真实信息。这篇没有对应的完整操作记录，不猜测这些字段，也不提供虚构填写方法。

### “注册完成”不是一个状态

| 状态 | 能说明什么 | 还不能说明什么 |
| --- | --- | --- |
| 注册表单已提交 | 账户创建流程已经开始 | 不能说明 KYC 已完成 |
| 可以登录 | 账户存在并可访问 | 不能说明法币功能可用 |
| KYC 已通过 | 身份验证完成 | 不能自动证明 GBP/FPS 入口存在 |
| GBP/FPS 入口可见 | 当前主路线需要的功能已经出现在账户里 | 仍未验证充值、兑换和出金 |

对这条路线来说，至少要确认 KYC 状态以及 GBP/FPS 入口是否实际可见，不能在“可以登录”时就把 Kraken 注册环节判定为完成。

注册阶段还需要准备自己控制的邮箱、密码和双重验证。这里不展开账户安全教程，但 Kraken 后面同时承接 Crypto 和法币，不能把安全设置当作无关步骤。

## 在 Kraken 创建 USDT 充值入口

这一步是[上一篇币安买入与提币](/moonlit-blog/posts/binance-buy-usdt-basics/)的接收端。币安提币需要一个外部地址，这个地址从 Kraken 的 USDT 充值页面生成。

基本顺序是：

1. 在 Kraken 进入充值页面。
2. 选择 USDT。
3. 查看账户当时实际支持的 USDT 网络。
4. 选择网络，生成对应充值地址。
5. 记录页面显示的最低充值数量、确认要求，以及是否存在附加标识。

网络选择的顺序不能反过来。不能先在币安挑一条手续费便宜的网络，再假设 Kraken 一定支持。正确顺序是先从 Kraken 当前提供的网络中选择，再回币安使用对应网络提币。

这里不写 Kraken 长期固定支持哪些网络，也不写一个固定的最低充值数量。网络列表、门槛和确认要求都可能变化，只能读取本次充值页面。

## 充值过程中有多个状态

从币安提交提币到 Kraken 可以使用 USDT，中间至少会经过这些状态：

| 状态 | 发生在哪里 | 表示什么 |
| --- | --- | --- |
| 提币已提交 | 币安 | 币安接受了提币请求 |
| 出现 TxID | 币安与区块链 | 交易已经广播，可以查询链上状态 |
| 链上确认中 | 区块链 | 交易正在获得确认 |
| Kraken 检测到充值 | Kraken | Kraken 已经发现交易，但余额可能仍在等待 |
| USDT 余额可用 | Kraken | 这笔 USDT 已经可以用于后续兑换 |

币安显示提币完成，不等于 Kraken 余额已经可用；区块浏览器显示交易确认，也不等于 Kraken 已经完成内部记账。

对 Kraken 充值这一环，完成标准是 Kraken 账户里实际出现可用 USDT 余额。如果网络不匹配，或者金额低于 Kraken 当时显示的最低充值数量，就不能预设它会正常记账。

这篇把状态和完成标准写全，但目前不声称这次充值已经实际完成。

## 把 USDT 换成 GBP

Kraken 节点的核心不是让 USDT 换一个平台存放，而是完成 Crypto-to-Fiat。USDT 在 Kraken 里可用以后，下一步就是把它换成 GBP。

### 先确认兑换路径

首先要检查实际账户中是否存在可用的 USDT/GBP 交易或兑换入口。如果能够直接从 USDT 换 GBP，就只需要一次兑换；如果实际账户没有直接路径，才需要研究是否存在中间币种。

不能在没有打开实际交易页面前，先假定交易对、费率或中转路径一定存在。

### 简单兑换和订单簿交易

Kraken 可能提供不同的兑换入口：

- **简单兑换**：平台给出一笔完整报价，确认后执行。操作直接，但需要看最终能得到多少 GBP。
- **订单簿交易**：在交易市场中选择订单类型和价格，成交结果取决于市场订单簿。

这两个入口不能只比较表面上显示的手续费。低损耗路线至少要记录：

- 是否可以直接交易 USDT/GBP。
- 当时的报价。
- 买卖价差。
- 交易手续费。
- 订单类型。
- 预计成交数量和实际成交数量。
- 最终进入法币余额的 GBP 数额。

### 市价单与限价单

- **市价单**强调尽快成交，但最终价格可能随着订单簿变化。
- **限价单**可以限定价格，但不保证立即成交。

这里不预先规定应该使用哪一种。实际选择要看当时的市场深度、价格和是否愿意等待。

兑换环节的完成标准不是“订单已经提交”，而是订单已经成交，Kraken 法币余额里实际出现可用 GBP。

## 从 Kraken 通过 GBP FPS 提到 iFAST

### 前置条件是 iFAST 已经可收 GBP

要从 Kraken 提出 GBP，首先需要一个能够接收 FPS 的同名银行账户。这条路线计划使用 iFAST Global Bank。

但 iFAST 目前尚未开户。开户需要地址证明，而[汇丰易存电子账单](/moonlit-blog/posts/china-proof-of-address-hsbc-yicun/)是否符合要求仍在验证。因此 Kraken 的 FPS 出金目前还不具备端到端测试条件。

这不影响把操作条件写清楚：

1. iFAST 开户完成。
2. 取得 iFAST 提供的 GBP/FPS 银行账户信息。
3. 在 Kraken 的 GBP 提现页面确认账户实际提供 FPS 方式。
4. 添加同名 iFAST 收款账户。
5. 核对最低提现金额、平台手续费和页面给出的预计处理信息。
6. 提交 GBP 提现。
7. 等待 iFAST 银行账户实际出现入账记录。

最低提现、手续费和处理时间都会变化，不能把某一次页面数字写成长期规则。

### 同名账户是一条连续条件

Kraken 的身份、iFAST 银行账户持有人和 FPS 收款人属于同一条资金链。添加银行账户时，需要逐项核对收款人姓名和 Kraken 页面要求的银行信息。

这也是为什么 iFAST 不是随便找一个银行账户替代就行：它既要承接 Kraken 的法币，又要在后面以同名银行账户向 Wise 首次入金。

### 提现也有多个状态

| 状态 | 能说明什么 |
| --- | --- |
| 银行账户已添加 | Kraken 已保存收款信息，还没有发起提现 |
| 提现已提交 | Kraken 接受了 GBP 提现请求 |
| Kraken 处理中 | 请求仍在交易所内部处理 |
| Kraken 已发送 | 资金已经离开交易所处理链路，但不能代替银行查账 |
| iFAST 实际入账 | Kraken 这个平台节点才算端到端完成 |

文章不会把“Kraken 已发送”写成“银行已收到”。FPS 这一环的最终完成标准是 iFAST 账户中出现对应 GBP 入账。

## 整个 Kraken 节点怎样互相依赖

```text
英国区账户 + KYC 通过
→ GBP/FPS 入口可见
→ 创建 Kraken USDT 充值入口
→ Kraken 出现可用 USDT
→ USDT/GBP 订单成交
→ Kraken 出现可用 GBP
→ iFAST 同名 GBP/FPS 账户已开通
→ Kraken 提交并处理 FPS 提现
→ iFAST 实际收到 GBP
```

每一个状态都是下一步的入口。KYC 没通过，后面的功能无法确认；USDT 没有成为可用余额，就没有资产可以兑换；GBP 没有实际成交，就没有法币可提；iFAST 没开好，就没有 FPS 收款账户。

## 实际操作时应该记录什么

| 阶段 | 记录字段 |
| --- | --- |
| 注册与 KYC | 账户地区、KYC 状态、证件类型、GBP/FPS 入口是否可见 |
| USDT 充值 | 网络、地址首尾、最低充值数量、TxID、状态变化、可用时间 |

这些数据用来比较真实损耗和定位卡点。公开写文章时，不需要暴露完整充值地址、银行账号或身份材料。

## Neverless 作为备用路线

如果 Kraken 的英国区或 GBP/FPS 条件无法成立，备用路线是 Neverless。它的国家和地区信息可以全部选择中国，后面走 EUR 和 SEPA，再进入 iFAST。

两条路线的法币和银行通道不同，不能直接拿一个注册条件替代另一个；当前也没有端到端实测结果证明哪条更好。

## 现在真正卡住的地方

这篇已经把 Kraken 从英国区注册写到 GBP/FPS 出金的完成标准。当前没有完成，不是因为文章主动停在注册，而是因为实际链路还有两个待验证部分：Kraken 内部的充值与兑换尚未实测，iFAST 又被地址证明卡在开户之前。

只要 iFAST 还没有可用的 GBP/FPS 收款账户，Kraken 节点就无法验证到最后一行。它最终是否跑通，要以 iFAST 实际收到从 Kraken 提出的 GBP 为准。
